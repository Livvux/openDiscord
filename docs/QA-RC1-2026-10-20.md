Machine: MacBook (macOS, Apple Silicon). Playwright 1.64.0 with its bundled Chromium, Firefox 1555 and WebKit 2370.

**Scope of the evidence.** Every result comes from a browser engine or from device emulation. No physical device was used: "iPhone 13" means Playwright WebKit with the iPhone 13 viewport and user agent, and "Pixel 7" means Chromium with Pixel 7 emulation. Microsoft Edge is not installed on this Mac and was **not tested**. Real Safari was not driven either, because safaridriver needs a settings change.

Notes:

1. WebKit runs with the service worker blocked (project `webkit`, see H1). Before that change, about 10 settings-based specs failed in WebKit, sign-out among them.
2. One run hit "Navigation to /app/friends is interrupted by another navigation to /app". This is a `page.goto` race in the spec.
3. Console-error and pageerror collectors pick up engine-specific logs for requests that a navigation aborts. WebKit logs "… due to access control checks." and "Load failed". Firefox logs `NS_BINDING_ABORTED`, React #412 ("Connection closed") and "Error in input stream". Chromium logs none of these. The product flow itself completed.
4. macOS headless Chromium decodes the fake VP8 camera far too slowly (`framesDecoded` 2, test needs more than 10). Audio passes. These tests also fail on `main` locally (recorded 2026-10-16) and pass in Linux CI (`CI` run 39251899132).
5. Playwright WebKit has no push daemon. `PushManager.getSubscription()` reloads the page and leaves it unscriptable (details in H1).
6. Playwright Firefox's `setOffline` does not apply to service-worker fetches. While `navigator.onLine === false`, the SW's network fetch still loaded `/app/settings` HTML. Then the page's own `/api/auth/get-session` failed with `NS_ERROR_OFFLINE` and Next showed "This page couldn't load". WebKit and Chromium show the offline page.

## Bugs found

### Product (fixed on this branch)

- **B1: DM header hides the peer's name on phones of 390 px and narrower (iPhone 13/14/15 and SE size).** The header's action buttons are `shrink-0` ("Call", "Devices and recovery", "Block person"). They squeeze the `min-w-0 truncate` `<h1>` to zero width, so the name of the person you are talking to disappears.
  - Engine-independent: it reproduced in Chromium at 390 px, and Pixel 7 at 412 px escaped only by width.
  - Fix: the "Devices and recovery" label becomes `max-sm:sr-only`, the same pattern the Call button already uses. The accessible name is unchanged.
  - Regression test: `e2e/dm-mobile-header.spec.ts` (mobile project, checks 390 and 375 px). It failed on the old build (heading hidden) and passes on the fix.
- **B2: Admin console overflows horizontally on iPhone in WebKit.** The badge's `sr-only` "open" span is absolutely positioned and escaped the tab strip's `overflow-x-auto` container. The document became 466 px wide in a 390 px viewport.
  - Fix: `relative` on the scroll container.
  - Regression test: the existing `scrollWidth <= innerWidth` assertion in `instance-admin.spec.ts` under the `iphone` project. It failed twice before the fix and passes after, with desktop/mobile Chromium still green.

### Product (minor, not fixed)

- **WebKit `pageerror` "Load failed".** In `dm-bootstrap-edge-cases:213` and `community-trust`, WebKit raises an unhandled promise rejection for a fetch that a navigation aborts. Some fetch is missing a `catch`, but the source was not pinpointed (the trace covers only the test context). It has no user-visible effect.

### Harness / engine (documented, not product)

- **H1: the service worker in Playwright WebKit.** Calling `reg.pushManager.getSubscription()` (from `push-settings.tsx` on `/app/settings`) reloads the page about 0.7 s after it opens. The reloaded page then never becomes scriptable.
  - Verified three ways: stubbing `getSubscription` removes the reload, `serviceWorkers: "block"` removes it, and CPU is idle (no busy loop).
  - Mitigation: the cross-browser config blocks the SW for `webkit` and `iphone`. The `webkit-sw` and `iphone-sw` projects keep it on for the PWA and push specs.
  - Needs a check in real Safari before it is ruled out as a product issue.
- **H2: Base UI focus guards on WebKit.** Base UI deliberately gives its focus guards `role="button"` on WebKit, so VoiceOver's cursor hits the focus trap, and axe flags them as unnamed buttons. `expectNoA11yViolations` now excludes `[data-base-ui-focus-guard]`.
- **H3: other harness and engine gaps.**
  - Chromium-only Playwright features: `newCDPSession` (passkeys, long-press touch, installability) and the `clipboard-read`/`clipboard-write`/`microphone` permission names (context-menus and the voice proofs).
  - Hard-coded "Chrome on Windows" in `account-privacy.spec.ts`.
  - Playwright Firefox ignores a `mouse.wheel` delta of ±100000 (community-catchup-scroll). 20 × 500 steps scrolled fine.
- **H4: local voice fixtures.** `voice-media-observer.ts` and `voice-three-browser.spec.ts` hard-code `7880` / `3200`. They were patched only for local runs and not committed.

## How to reproduce

```sh
source ~/.cache/od-dev/test.env
export DATABASE_URL=postgres://opendiscord:opendiscord@localhost:5433/opendiscord_rc1_qa E2E_PORT=3310 LIVEKIT_URL=ws://localhost:7895
cd apps/web && pnpm db:migrate && pnpm build
pnpm exec playwright install firefox webkit
# LiveKit: livekit-server --config <yaml with port 7895, rtc tcp 7896, udp 51400-51500, node_ip 127.0.0.1>
#   (base suites: room auto-create on; voice-product: room.auto_create false, as in voice-product.yml)
CI=true GITHUB_ACTIONS=true pnpm exec playwright test --project=desktop --project=mobile
CI=true GITHUB_ACTIONS=true pnpm exec playwright test --config playwright.cross-browser.config.ts --project=firefox
CI=true GITHUB_ACTIONS=true pnpm exec playwright test --config playwright.cross-browser.config.ts --project=webkit --project=webkit-sw
CI=true GITHUB_ACTIONS=true pnpm exec playwright test --config playwright.cross-browser.config.ts --project=iphone --project=iphone-sw
for b in "" firefox webkit; do VOICE_PRODUCT_BROWSER=$b CI=true GITHUB_ACTIONS=true pnpm exec playwright test --config playwright.voice-product.config.ts; done
```

Run one cross-browser project group at a time: sign-in is rate-limited per IP, and `instance-admin` uses instance-wide data. Voice specs that use `assertDisposableVoiceCi` need `e2e/fixtures/voice-media-observer.ts` patched temporarily to your LiveKit and server ports.
