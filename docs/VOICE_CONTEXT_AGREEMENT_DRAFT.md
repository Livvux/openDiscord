# S6-A1 authenticated context agreement — unreachable Draft

This dependent preparation branch adds an in-memory agreement ledger owned privately by the existing native VoiceCryptoOwner. It does not activate an encrypted product call, change HTTP/service/schema/SFU/Worker/UI paths, or authorize deployment. Existing production voice remains basic voice.

The product-facing `agreementPort()` omits `setControlContext` and primitive `receive`. Explicit `selectAudience` records the local exact roster consent; remote controls cannot select or admit parties. The deterministic lowest-member leader creates the epoch and reference in `createContextOffer`, with sequence allocated by its lifetime private ledger across audience choices. Callers fan out strict offers and accepts through the same admitted native Olm Owner. No self-SAS or self-Olm is required.

`receiveAgreement` and the primitive `receive` are alternate facades over one native receive implementation. The primitive facade fails closed on context controls. The agreement facade first validates current canonical parties, own recipient and native verified sender/envelope. Only missing local admission/selection returns a bounded thin context-not-ready result, with real ACK/flush and no proposal/capability/consent authority; later explicit complete-roster selection and a fresh higher-sequence offer retry are required. Foreign/selected-audience/native/schema/recipient faults remain fatal. Context and pending material results carry same-Owner WeakMap capabilities. Receiving an offer creates only a batch-local candidate. `stageOfferedContext` validates the private ledger's ordering, exact selected revision and local consent before persistent staging. `acceptContextControl` counts only genuine received capability slots. `installContext` requires the independent own-plus-every-remote barrier and uses the existing native drain/installer. Only then are pending material controls returned once for later media handling; no key import/readiness/capture occurs here.

The pure ledger retains a single proposal with thin accept/material slots, measures canonical retained payload against 12 KiB, and enforces a ten-second original deadline, one offer per second, eight accepted transitions per ten seconds and bounded restart coalescing. This is a canonical payload bound, not a heap guarantee. Retained proposal tables hold all six exact ordinary-string party fields in immutable tuples; canonical party objects are transient views. All outstanding event refs are bounded, measured with prospective ledger metadata, consumed on application or abandoned before the next poll. Media controls require the exact agreed proposalSequence (wire q); only the old primitive context path permits omission. The party-table-v2 identity codec and 8192-byte whole native request limit remain unchanged.

New focused tests cover pure replay/consent/order/bounds and three independent Node Owners using real PostgreSQL handleVoiceCrypto, real public SDK SAS comparison before confirmation and separate explicit admissions. These are Node native/service tests, not authenticated browser/media or production acceptance. The inherited sixteen real eight-party whole-request size assertions and six positive-before-negative native codec regressions remain unchanged.

Verification is exclusively canonical remote GitHub CI. No local heavy builds, type-checks, tests, SDK/native probes or Docker are run. Parent and final exact-head full CI plus independent Root code/security reviews remain gates before any further activation work. Migrations 0030–0032 remain isolated CI only.
