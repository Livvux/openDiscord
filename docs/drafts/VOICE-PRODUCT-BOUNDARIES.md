## Implemented boundaries

`lib/dm/enrollment.ts` is the canonical existing parser extracted unchanged from DM client; its read-only helper returns only id/secret or null. It reads the existing localStorage entry once, catches unavailable storage, never repairs/removes/registers and imports only Zod. Voice has no DM native/history/client import. DM runtime continues using exactly its original parser.

`server/voice-http.ts` derives identity only through real requireUser(request.headers), rejects missing/foreign exact configured BETTER_AUTH_URL origin and cross-site requests, and requires application/json. No request URL fallback, caller user/session identity, CORS or response handler exists. The exported response headers specify private,no-store; any future transport must apply that contract to every success and error and use bounded streaming JSON parsing. No endpoint/manual endpoint test is claimed.

`grantBoundVoiceMedia` takes the existing serialized control lock/revalidation path, checks current owned session/anchor/member possession, nonce, active call/lease, exact generation, Connect, block policy and current Speak/Video inside one database transaction. It does not heartbeat or extend freshness. It returns an inert snapshot with exact `voice:<channelUUID>:<callUUID>:<generation>` room, `v1:<memberUUID>` identity, least source set, data disabled and expiration bounded by session, lease and 60 seconds. Canonical whole-segment room parsing rejects malformed/extra/noncanonical generations; prefix/substrings do not authorize ownership.

`createBoundVoiceToken` is a new unused export. It receives the committed grant before constructing the local AccessToken, floors its lifetime conservatively below remaining freshness and 60 seconds, explicitly disables data and own-metadata updates, and refuses expired signing/grant results. No SFU/network work runs under control locks. Existing createVoiceToken/joinVoice/provider remain untouched. Public LiveKit server SDK 2.19.1 source/declarations (`src/AccessToken.ts`, `src/grants.ts`) are the documentation fallback verified locally: numeric ttl is seconds, addGrant accepts source restrictions/data disable, toJwt locally signs HS256 with exp/nbf/sub. No dependency or lockfile changes.

Postcommit invalidation may race signing and delivery. Short JWT TTL bounds stale joins only; it cannot revoke delivered tokens, prove native SAS/audience admission, or end SFU-refreshed sessions. Generation changes require a distinct room, fresh media key/owner epoch and real postcommit lifecycle reconciliation/cleanup before activation. Native SQL cascades cannot directly invoke SFU cleanup. There is deliberately no effects consumer or no-op dispatcher here, and no claim of immediate revocation, universal 30 second SFU removal or encrypted product acceptance. PR57/native-generation proof and the complete media/readiness/route/UI/key lifecycle gates remain mandatory.
