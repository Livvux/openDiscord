# Internal owner/service integration candidate

PR61 adds `apps/web/tests/voice-owner-service.integration.test.ts` against the real PostgreSQL service and public SDK18.9. The fixture creates actual users, sessions, enrollment-only DM devices, community permissions, joins, 30-second leases and heartbeat snapshots. It imports neither the unit directory nor the generation feasibility server. Only the Node Web Lock manager is replaced; the production guard remains required.

The tests compare real emoji and decimal SAS before both explicit confirmations, admit peers separately and require successful bidirectional typed Olm decryption. Public SDK spies observe decimal values or place deterministic barriers around the original native completion; they do not manufacture success. Transport barriers surround actual `handleVoiceCrypto` calls. Retirement assertions retain original native body, ID and transaction while independently identifying transport attempts. A before-commit source-generation denial is expected to stop the owner; it is not treated as a recoverable timeout.

Additional cases cover genuine absent device query results, session/anchor/lease denial without enqueue or lease extension, retained prior admission through actual membership removal, generation/epoch/audience fences after genuine successful control decryption while ack HTTP delivery is held, and lock retention during pending native cleanup. DM cryptographic tables are read before and after the positive owner flow. Enrollment anchors are not opened as native DM machines.

## Open acceptance

Runtime checks and independent review must pass on the exact candidate before these assertions become evidence. No local native execution is authorized for this worktree. Canonical CI provides the disposable PostgreSQL runtime. These tests are not browser Web Lock, route, HTTP security, media, SFU, UI or production acceptance.

The complete S4 matrix remains open: separately encrypted generation-only/epoch-only/audience-only invalid payloads; current-target retirement and reverse send/retire response order; unknown-commit retry; actual claim absence/retry and truthful remote signature refusal reachable through public owner APIs; source permission denial; and registry first-observation evidence at dispatch. The current public owner validates outgoing control context before encryption, so crafting invalid encrypted controls needs an independent genuine public SDK test peer; private owner machine extraction is prohibited. A departed peer is no longer a current `query(memberIds)` target, and held old-generation requests correctly hit real service authority checks. No invented keys, fabricated claims, rewritten native request or test-only production bypass may fill these gaps.
