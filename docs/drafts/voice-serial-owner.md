# Unreachable serial Voice Olm owner preparation

This additive draft starts S3 against strict service parent 48dce82. Nothing imports or activates the owner. It uses the public pinned 18.9 SDK, independent unnamed memory storage and a runtime one-consumption capability backed by the held `opendiscord.voice:<accountId>` Web Lock. Native cleanup retains that lock until the serialized queue actually stops; there is deliberately no timeout release that could allow two native owners.

Native operations, request observation and completion run in one executor; transport waits outside it. A bounded registry preserves original IDs/type/body digest and local first observation generation, with generation-scoped transport transaction IDs kept separate. Completion reserves before awaiting native completion. Transition fences publication synchronously, publicly cancels known SAS, and retires only known old single-target ToDevice work or narrowly attributable cancellation output. Unknown first-observed transition ToDevice work fails closed. Upload/bootstrap never retires. Native exceptions and schema failures end the owner.

The typed control port validates exact call/generation/epoch/audience/member/device/nonce/publisher binding and native verified sender/envelope. It generates no media key, changes no media worker, and performs no prepared/key-ready/admission side effect on receive. Explicit SAS confirmation and explicit admission are separate APIs.

## Pre-native sync resource boundary

The actual service caps the entire normal send request at 8192 UTF-8 bytes and stores only `{sender,type,content}`. Its canonical call/member sender is 98 ASCII bytes, the longest supported event type is 26, and JSON envelope punctuation adds 34: 158 bytes around content. The owner conservatively permits 256 bytes of envelope allowance, giving 8448 bytes per serialized event. At most 64 events, including array brackets/commas, give an explicit 540737-byte native event-array cap. Each exact serialized event is byte-counted and strictly validated before that same string can reach `receiveSyncChanges`; an early UTF-16-length rejection also avoids encoding an already oversized string. Sender must be an exact current other voice member, and type/content must match the existing supported strict server schema. Auxiliary data accepts only the service's `signed_curve25519` count (integer 0–100) and at most its one supported unused-fallback label.

Plain JSON negative tests cover ASCII/UTF-8 size, count, auxiliary maps and envelope shapes. A public SDK spy is a hard tripwire that never invokes native code: it must record zero calls on rejection, followed by fatal owner cleanup and actual ownership release. Future HTTP streaming/response-parser limits remain a separate S5 boundary. No oversized/native parser probe is used.

## Late transport outcome classification

Each native request attempt retains its original immutable generation binding, operation key and owner revision, plus the entry's active-attempt identity. Both transport success and rejection return to the same serial executor before validation, fatal policy or native completion. A proven superseded/terminal attempt raises `VoiceGenerationInterrupted`; it neither completes native work again nor closes the retained current owner. The original interrupted operation is not reported successful. Current transport/schema/native failures remain fatal, and a native completion exception is never reclassified as an obsolete HTTP failure. An exact same-generation retry retains its original transport request/body; a later context owns a fresh attempt record. Unit regressions cover obsolete transport rejection before, during and after actual native retirement completion, plus current-error fatality. Real service S4 regression remains its own acceptance gate.

The direct sync/ACK/bootstrap exchange path also captures a frozen binding and revision in the executor, then serially classifies both success and rejection before applying fatal transport policy. Sync processing rechecks the receive revision before even parsing a result returned across an async boundary. Four held sync/ACK rejection tests cross generation or same-generation epoch drains and require a subsequent genuine verified peer control to decrypt successfully; current sync/ACK failures still end the owner.
